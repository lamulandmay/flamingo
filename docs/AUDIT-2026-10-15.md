**Flamingo product and codebase audit**

15 October 2026. Audited the current working tree, including the uncommitted sidebar, bookmarks, and file-operation changes.

**My assessment is that Flamingo adds another place to manage work without yet reliably removing work elsewhere.** Its strongest idea is durable thinking attached to real files. The implementation has substantial foundations, but the workflow from finding evidence, to recording a thought, to returning to that exact place remains incomplete. That is a plausible reason you do not reach for it voluntarily; it is a product inference, not a claim to know your private motivations.

The most consequential problem is invisible incompleteness. A missing result might mean no match, skipped extraction, a parser failure, a stale index, a truncated result set, or the wrong scope. The interface often presents these states identically. You consequently have to verify Flamingo with the applications and folders it is meant to help you navigate.

The audit covered all 122 Swift files in `Sources` (25,955 lines), the 57 Swift test files and their coverage across seven test bundles, the package manifest, build/release scripts, resource configuration, and fixture/plan structure. Review depth varied across test bodies and fixture-generation artwork. Generated binaries were not decompiled. No application source was changed.

P1 below means an issue to resolve before relying on the core daily workflow. P2 means a material reliability or completeness problem. Product gaps are distinguished from unintended defects.

1. **P1 — Exact-place navigation is missing for most supported formats.** PDF and media receive `jumpRequest`; PowerPoint, Word, spreadsheets, text, and other files receive only a URL and modification date. `stepAnchor` can change the displayed slide/cell/line anchor without moving the preview. A search result or citation can therefore claim to land on evidence while displaying another place, and a captured thought can inherit an anchor that does not correspond to what the user sees. This is the central promise of the application. Implement real navigation where possible and explicitly communicate unsupported locations elsewhere. Evidence: [PreviewPane.swift:26](/Users/allenwu/claude/flamingo/Sources/Flamingo/PreviewPane.swift:26), [Quick Look wrapper:4](/Users/allenwu/claude/flamingo/Sources/Flamingo/PreviewQuickLook.swift:4), [AppState.swift:828](/Users/allenwu/claude/flamingo/Sources/Flamingo/AppState.swift:828). Confirmed in source; the older slide mismatch report is consistent with this current wiring.

2. **P1 — A failed capture can discard the thought and still record apparent success.** Enter clears the capture presentation and destroys the editor before persistence succeeds. The shell catches a save error only by writing to stderr and still records a `commented` event. Read-only folders, disconnected volumes, and failed writes therefore have no recoverable draft or useful failure UI. Failed rail deletion similarly hides a comment optimistically without rolling it back when storage fails. Keep drafts until acknowledged persistence; offer retry/copy; record the trail only after success. Evidence: [CaptureController.swift:223](/Users/allenwu/claude/flamingo/Sources/FlamingoCapture/CaptureController.swift:223), [CapturePanel.swift:112](/Users/allenwu/claude/flamingo/Sources/FlamingoCapture/CapturePanel.swift:112), [AppState.swift:868](/Users/allenwu/claude/flamingo/Sources/Flamingo/AppState.swift:868), [CommentsRail.swift:211](/Users/allenwu/claude/flamingo/Sources/FlamingoCapture/CommentsRail.swift:211). Confirmed control flow; no failure-path UI test.

3. **P1 — Extraction failures become persistent, invisible search holes.** Parser/fallback failures collapse into empty extracted content, which is stored with an apparently successful file stamp. Unchanged files are then skipped on later scans. There is no persisted success/partial/failure state, coverage indicator, or retry schedule. A temporary import failure can therefore remain until a force reindex or file edit. Preserve last good content, record coverage/error state, and retry failed work. Evidence: [Extract.swift:91](/Users/allenwu/claude/flamingo/Sources/FlamingoExtract/Extract.swift:91), [IndexStore.swift:458](/Users/allenwu/claude/flamingo/Sources/FlamingoIndex/IndexStore.swift:458), [IndexStore.swift:582](/Users/allenwu/claude/flamingo/Sources/FlamingoIndex/IndexStore.swift:582), [unchanged-file check:126](/Users/allenwu/claude/flamingo/Sources/FlamingoIndex/IndexStore.swift:126).

4. **P1 — Whole-Mac scanning and watching disagree.** Initial scanning includes hidden files, but the watcher discards events containing dot-prefixed components. Hidden files and their comments become stale. The advertised `.flamingo/ignore` is also ignored by the watcher; only the legacy `.flamingoignore` triggers a rules refresh. Separately, watching `/` constructs a `//` prefix and loses ordinary descendant paths. These are three defects in one freshness contract. A compiled probe confirmed that `.config/a.txt`, its hidden-file sidecar, and `.flamingo/ignore` all classify as no event. Evidence: [VaultWatcher.swift:104](/Users/allenwu/claude/flamingo/Sources/FlamingoIndex/VaultWatcher.swift:104), [root handling:129](/Users/allenwu/claude/flamingo/Sources/FlamingoIndex/VaultWatcher.swift:129), [classification:197](/Users/allenwu/claude/flamingo/Sources/FlamingoIndex/VaultWatcher.swift:197). Unify scanner, watcher, and ignore policy and test create/edit/delete at each scope.

5. **P1 — The app can disagree with itself about the current file and folder.** A graph click selects B inside GraphModel without updating the shell, so the rail and capture target can still refer to A. Folder activation likewise updates only the graph's local scope. In the other direction, palette/search/bookmark navigation changes the selected file without updating `selectedFolder`; revealing the sidebar row deliberately suppresses its selection callback. Vault opening does not reset that folder either. Graph scope and the destination for New Note can therefore remain attached to a previous folder. Establish one shared navigation state and separate selecting from opening. Evidence: [GraphModel.swift:551](/Users/allenwu/claude/flamingo/Sources/FlamingoGraph/GraphModel.swift:551), [folder activation:303](/Users/allenwu/claude/flamingo/Sources/FlamingoGraph/GraphModel.swift:303), [AppState.swift:708](/Users/allenwu/claude/flamingo/Sources/Flamingo/AppState.swift:708), [targetFolder:482](/Users/allenwu/claude/flamingo/Sources/Flamingo/AppState.swift:482), [Sidebar.swift:438](/Users/allenwu/claude/flamingo/Sources/Flamingo/Sidebar.swift:438).

6. **P1 — Capture can stall while the thought is still in your head.** Frontmost-app title matching can enumerate the entire vault synchronously on the main actor, with a cache lasting only 30 seconds. Link completion separately rescans candidates off-main, then constructs its matcher and performs completion matching on the main actor. An optimized isolated probe of the actual matcher with 100,000 synthetic paths measured 916 ms construction and 133 ms for one query. Those are algorithm timings, not measured live app latency, but the UI runs that algorithm synchronously. Reuse the session catalog and move preparation/ranking off-main. 7. **P1 for this user's bilingual workload — Chinese substring recall is inconsistent.** Search returns the first nonempty matching strategy, so a successful FTS match prevents the substring fallback from contributing other valid files. Reproduced with `a.txt = 定价策略` and `b.txt = 我们的定价策略在第三季度调整。`: searching `定价策略` returned only A, although both indexed texts contain the phrase. 8. **P2 — Search in Folder is unreliable in ordinary folders.** Its parser splits on spaces, so a generated query for `Kestrel Works` treats `Works/` as search text and scopes to `Kestrel`. It also searches globally with a cap of 300 sections and 300 comments, then filters by folder; valid local results outside those global caps disappear. The displayed count is a count of returned hits, without indicating truncation. Scope should be a structured query parameter applied before ranking/limiting, with pagination or a visible cap. 9. **P2 — The documents you most need help reading can be invisible.** PDFs use `PDFPage.string` without OCR. Image-only scanned worksheets/papers are effectively unsearchable, and the four-second reading budget leaves later pages empty without showing partial coverage. Images have OCR, but that capability is not connected to PDF pages. Separately, the shell filters files over the extraction limit and cloud placeholders before sending them to the index, so those files never receive even filename/size metadata rows in the index. They may appear in quick-open but be absent from content search. The index discards full text when sections account for at least 90% of its length. Represent supplementary content explicitly instead of inferring duplication from character counts. The application has one window, disallows tabs, and does not preserve a project workspace with several open documents and locations. Decide which work Flamingo will actually own: a lightweight synthesis note beside sources, or an exceptionally good bridge into native editors. **What is already worth keeping.** The native shell, atomic sidecars, stable identity and rename reconciliation, broad format parsers, FTS/hybrid retrieval, citation handling, torn-trail-write recovery, input-method support, and graph layout machinery are substantial work. Bookmark groups, saved searches, named trails, and persisted thoughts already provide partial organization and continuity. The visual system is coherent. The issue is that several well-developed components do not yet form a dependable user workflow. Another decorative pass would leave the strongest blockers intact.

The demo reinforces this distinction. Its content deliberately follows one coherent pricing story, and its sidecars and trail are written directly from predetermined records. That makes it a useful showcase, but bypasses the actual capture, selection, linking, and resume paths. ASCII fixture paths with shallow directories also miss ordinary space/Unicode/deep-folder cases. Existing graph and trail scale tests are valuable; realistic integrated workflow coverage is what is missing. **The next version should earn use through three concrete workflows.**

| Order | User outcome | Acceptance condition |
|---|---|---|
| 1 | Capture a thought without losing context | Shortcut responds promptly; target is visible and correct; failed persistence retains the draft; source app/location survives; captured text can be recovered after restart |
| 2 | Find evidence and return to its actual location | Representative Chinese files, scans, footnotes, renamed files, large files, and long sections remain discoverable; results disclose partial coverage; citations visibly land on supported locations |
| 3 | Resume a real piece of work | A project keeps its sources, synthesis note, questions, and locations; native-app activity can contribute by explicit choice; file moves do not break continuity |

For implementation, first fix save acknowledgment and shared file/folder state. Then unify indexing/watching policy and expose coverage, repair retrieval/anchor navigation, and build a usable project surface. Make Ask and Graph support that surface with cited answers and explained relationships. Defer additional graph physics, more model/provider breadth, more icons, and more format names until these workflows work on your actual research and school folders.

A useful acceptance exercise is a real bilingual project containing a scanned PDF, a presentation, a spreadsheet, and working notes: find a fact, inspect its exact source, record a linked thought, rename a file, close the app, and resume the following day. Also force a save failure and an extraction failure. Completion means the thought and its evidence remain recoverable with clear status throughout; a green unit suite alone cannot demonstrate that.

Additional lower-priority source findings: scoped external graph neighbors can expand transitively depending on edge order; graph labels can make same-named files hard to distinguish; trail rename errors are discarded after optimistic UI updates. These belong behind the trust and daily-work fixes above.
